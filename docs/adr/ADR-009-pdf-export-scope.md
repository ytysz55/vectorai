# ADR-009 — PDF export remains outside the E6 release contract

- **Status:** Accepted
- **Context:** Cut-ready SVG must retain physical dimensions, path closure, and topology. PDF conversion is a separate backend whose geometric and renderer equivalence must be independently verified; a successful PDF write is not a topology proof.
- **Decision:** E6 ships **SVG only** as the authoritative editable/cut-ready artifact. Do not put a PDF exporter in the engine, default API, or release acceptance path. Inkscape may be used as an **unbundled, local, opt-in experiment** to export a validated SVG. The generated PDF must not be advertised as certified cut-ready until its own path, physical-scale, and raster-renderer gates exist. Do not rasterize the SVG into a PDF and call it vector export.
- **Alternatives considered:** Inkscape CLI (local vector PDF experiment; GPL program with redistributable/bundling review outstanding), CairoSVG (LGPLv3, new runtime/Cairo dependency and independent parity validation), and bitmap-in-PDF (rejected because it loses editable vector paths). resvg is a rasterizer, not a PDF export backend. See [SPIKE-019](../spikes/SPIKE-019-e6-pdf-export.md) and official [Inkscape licensing](https://inkscape.org/about/license/), [Inkscape CLI](https://inkscape.org/doc/man/inkscape-man.html), and [CairoSVG documentation](https://cairosvg.org/documentation/).
- **Consequences:** No optional PDF button or PDF package dependency in E6. E7/E8 may add PDF only after an independent backend decision, dependency/legal inventory, at least three-renderer raster agreement on the PDF, path-vector/closure checks, and a millimetre-to-PDF-point tolerance gate. Original SVG and its validation report remain the source of truth.
- **Validation evidence:** The 32 mm cut-outline experiment exported to a 90.708661 × 90.708661 pt vector PDF (`32 × 72 / 25.4 = 90.7086614`). Its content stream contains move/line/fill operators rather than a raster image. This is a scale/vector-content spot check only, not PDF renderer parity.
- **Review trigger:** A supported PDF pipeline can prove path topology, physical scale, renderer equivalence, dependency license compliance, resource bounds, and deterministic semantic evidence across both supported OSes.
