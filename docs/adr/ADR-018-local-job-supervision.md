# ADR-018 — Supervised local job process and fail-closed publication

- **Status:** Accepted for E7 API-001
- **Context:** The E3 demo endpoint runs a CPU-bound pipeline synchronously in the FastAPI event loop. An E7 upload/status/cancel/artifact contract must remain responsive and must not confuse cancellation of a Python Future with stopping the native renderer subprocess.
- **Decision:** Keep the synchronous demo route for compatibility. New `POST /v1/jobs` admits exactly one worker process per API instance; excess work returns typed `429 RESOURCE_LIMIT`, **not** a hidden queue. The worker writes a private result; the API supervisor alone publishes atomic, versioned status records. Only after a process has exited successfully, the engine's atomic bundle exists, its manifest identity agrees with the result, and cancellation has not won can artifact URLs be published. Running cancellation terminates the owned worker and its descendant renderer processes before publishing `canceled`. A 180-second wall deadline kills and reports `failed/RESOURCE_LIMIT`.
- **Durability:** On startup, an `accepted`/`running` record from an interrupted instance becomes `failed/JOB_INTERRUPTED`. Completed records and artifacts remain local. There is no automatic retention, cross-process lock, crash-proof orphan-process recovery, or OS memory sandbox; an abrupt API crash may leave a worker alive, but no nonterminal record is treated as successful. Never delete live staging files; a stopped worker's staging is cleaned after its terminal status is set. Artifact URLs are allowlisted and partial or symlink files are not served.
- **Alternatives:** In-process `asyncio` tasks / `ThreadPoolExecutor` were rejected as hard-cancellation mechanisms because cancellation does not stop CPU work or renderer children. An unbounded queue and keyed deduplication are deferred to API-002. Binding to LAN or adding hosted processing remains out of scope per ADR-016.
- **Consequences:** Process startup adds local latency; each API instance must exclusively own its jobs directory. `geometric` and `stroke` are the only modes claimed by the new endpoint until the other optimizer profiles are wired. The legacy endpoint's labels are not evidence of distinct optimized outputs. API-002 must design cross-process admission/idempotency and stronger crash/process-tree handling before multi-worker service or pilot release.
- **Validation evidence:** `python/tests/test_job_api.py`, `python/tests/test_job_supervisor.py`, `python/tests/test_job_cancel_renderer.py`, `schemas/local-job.schema.json`; legacy loopback regression in `python/tests/test_local_api.py`.
- **Review trigger:** API-002 queue/idempotency, a server with more than one API process, retention/cleanup policy, memory sandbox, or a hosted API proposal.
